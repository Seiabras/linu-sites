Uma cafeteria, cinco jeitos de fazer

O mesmo prompt foi para três IAs (ChatGPT, Gemini e DeepSeek). Fiquei com a versão do DeepSeek, estudei e reconstruí o código passo a passo em CSS puro; depois refiz a mesma página com quatro frameworks de CSS, cada um de uma escola diferente. O conteúdo, as cores e o modo padaria de dia são os mesmos nas cinco: muda só o jeito de escrever.

No rodapé de cada versão há a mesma lista, para trocar de uma para outra em qualquer direção.

O que muda quando entra um framework

No CSS puro, eu escrevo tudo: o tamanho das colunas, o menu do celular, a cor de cada botão. Um framework traz parte disso pronta. O preço é aprender o jeito dele e carregar o que ele traz. Cada um dos quatro escolhe um jeito diferente:

Quanto cada uma pesa

  • Tailwind é a mais leve porque o compilador deixa só as classes que a página usa: 0,7 KB.
  • Pico vem logo depois: 11 KB que já desenham a página inteira, porque estilizam as tags, e não classes.
  • Bootstrap e Bulma pesam mais porque trazem dezenas de componentes, mesmo que a página use só a grade e o menu; o Bootstrap ainda traz o JavaScript dele.

O mesmo cartão do cardápio, nos cinco

O que aconteceu de verdade, em cada uma

  • Bootstrap: ele já tem um .card, com fundo branco e borda; o cartão do tema virou .card-aurora para os dois não se misturarem. A barra de cima só abre no celular com o JavaScript dele.
  • Tailwind: o HTML ficou cheio de classes (flex items-center justify-between gap-4), mas nada brigou com o tema, porque as classes dele não têm nome de parte.
  • Bulma: ele também tem .card, .hero e .section, os mesmos nomes do tema. Usei a versão em que todas as classes dele começam com bulma-. Cada cartão precisou de uma div de coluna em volta, porque no Bulma o espaço entre os cartões é o recheio da coluna.
  • Pico: como ele desenha as tags, desenhou coisas que eu não pedi. O painel do laboratório tem role="group" (para o leitor de tela) e o Pico o transformou numa fileira de botões grudados; a letra da página crescia até 131% nas telas largas; e a barra de intensidade ficou com o trilho cinza dele. As duas primeiras eu corrigi; a terceira ficou, para mostrar.
  • Nas cinco: o JavaScript é o mesmo jeito de fazer (JavaScript puro). O Tailwind, o Bulma e o Pico usam até o mesmo arquivo, porque o script não depende de como o CSS foi escrito.

Quando usar cada um

CSS puro

Quando o visual é muito próprio (como o neon e a padaria) e o site precisa ser leve. Pede mais tempo, mas não carrega nada que não use.

Bootstrap

Quando é preciso montar rápido telas comuns (formulários, menus, janelas) e o peso extra não importa, como num painel interno.

Tailwind

Quando o time quer o layout visível no HTML e um CSS final pequeno. Exige um passo de compilação e um HTML carregado de classes.

Bulma

Quando se quer componentes prontos sem JavaScript nenhum, com nomes fáceis de ler (is-4, is-multiline).

Pico

Para um site simples ficar bonito quase sem esforço: um blog, uma documentação, um formulário. Num visual muito próprio, ele atrapalha mais do que ajuda.
